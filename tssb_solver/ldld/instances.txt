# The instances of the study: one per line, the name, the axis it belongs
# to and the arguments of the generator. All of them are PyPSA networks
# written by the generators in gen/ and converted by pypsa2smspp.
#
#   scaling    units in {10, 20, 50, 100} x horizon in {24, 168, 720}
#              (a day, a week and a month at hourly resolution), 5
#              scenarios, 5 seeds each: how the methods scale, the seeds
#              giving the spread at each size
#   scenarios  s in {3, 5, 10, 20, 50}, 40 units, 96 periods
#   buses      b in {1, 2, 4, 8, 15}, 80 units, 96 periods, 3 scenarios
#   tree       c x d leaves of a three-stage tree, c climates over d
#              demands each, 40 units, 96 periods
#   cfl-size   stochastic capacitated facility location: the ORLib
#              instances of 16 x 50, 25 x 50, 50 x 50 and 100 x 1000
#              facilities x customers, 4 per size, each with 10 scenarios
#              of the demands
#   cfl-scen   cap131 (50 x 50) with 5 to 100 scenarios
#   mmcf       stochastic multicommodity network design: the Canad
#              instances p33-p36 (20 nodes, 226 arcs, 40 commodities) and
#              p41-p44 (20 nodes, 292 arcs, 40 commodities), with 3 and 5
#              scenarios of the demands and complete recourse (the demand
#              the network built cannot carry costs 10 times the dearest
#              unit cost), which Benders with Lagrangian subproblems needs
#
# An instance whose name starts with tuc_ is a TwoStageStochasticBlock
# (gen/gen_thermal_tssb.py); one whose name starts with ttr_ is a
# MultiStageStochasticBlock (gen/gen_thermal_tree.py), which comes with the
# TwoStageStochasticBlock of the same leaves, <name>_2s, since on the tree
# only the recursive form applies (a LagBFunction needs the FRealObjective
# that a TwoStageStochasticBlock has not) and the other methods run on the
# flat equivalent, whose optimum and bound are those of the tree. The seed
# of an instance is in its name (_k<seed>, the default one when absent), so
# that the files are rebuilt identical from this list. An instance whose
# name starts with cfl_ is a TwoStageStochasticBlock over a
# CapacitatedFacilityLocationBlock (gen/cfl_tssb_gen), whose instance file
# is given relative to the data of the CapacitatedFacilityLocationBlock
# module (CFL_DATA); its name says the size (f<facilities>_c<customers>),
# the number of scenarios and the ORLib instance it comes from. An
# instance whose name starts with mmcf_ is a TwoStageStochasticBlock over an
# MMCFBlock (gen/mmcf_tssb_gen), out of a Canad instance of the tests of the
# MMCFBlock module (MMCF_DATA).
#
