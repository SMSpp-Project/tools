# The instances of the study: one per line, the name, the axis it belongs
# to and the arguments of the generator. All of them are PyPSA networks
# written by the generators in gen/ and converted by pypsa2smspp.
#
#   scaling    units in {10, 20, 50, 100} x horizon in {24, 168, 720}
#              (a day, a week and a month at hourly resolution), 5
#              scenarios, 5 seeds each: how the methods scale, the seeds
#              giving the spread at each size
#   scenarios  s in {3, 5, 10, 20, 50}, 40 units, 96 periods
#   buses      b in {1, 2, 4, 8, 15}, 80 units, 96 periods, 3 scenarios
#   tree       c x d leaves of a three-stage tree, c climates over d
#              demands each, 40 units, 96 periods
#
# An instance whose name starts with tuc_ is a TwoStageStochasticBlock
# (gen/gen_thermal_tssb.py); one whose name starts with ttr_ is a
# MultiStageStochasticBlock (gen/gen_thermal_tree.py), which comes with the
# TwoStageStochasticBlock of the same leaves, <name>_2s, since on the tree
# only the recursive form applies (a LagBFunction needs the FRealObjective
# that a TwoStageStochasticBlock has not) and the other methods run on the
# flat equivalent, whose optimum and bound are those of the tree. The seed
# of an instance is in its name (_k<seed>, the default one when absent), so
# that the files are rebuilt identical from this list.
#
